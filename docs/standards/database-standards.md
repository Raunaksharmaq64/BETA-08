# Database Architecture & Governance Standards

- **Title:** Relational Database Governance & Storage Standards
- **Purpose:** Mandates schema partitioning, migration lifecycle rules, indexing strategies, and cross-service boundary protection.
- **Status:** APPROVED
- **Owner:** Database Architect (UNASSIGNED)
- **Last Updated:** 2026-10-31

---

## 1. Schema Authority & Partitioning
* **Relational Engine:** PostgreSQL 16+.
* **Schema Isolation:**
  - `career_core`: Owned exclusively by Core Career Engine (`backend/app/modules/`).
  - `leadhunter_db`: Owned exclusively by LeadHunter AI (`services/leadhunter/`).
  - `startup_intel_db`: Owned exclusively by Startup Intelligence (`services/startup_intelligence/`).
* **Strict Boundary:** Cross-schema direct SQL joins (`SELECT ... FROM career_core.users JOIN leadhunter_db.leads`) are **strictly forbidden**. Inter-service data sharing must occur via REST contracts.

---

## 2. Table Design & Primary Keys
* **Naming:** Plural snake_case nouns (e.g., `users`, `job_matches`, `leads`).
* **Primary Keys:** Every table must have a primary key column named `id`. Use UUIDv4 (`UUID`) for public/distributed entities and `BIGINT` for high-throughput append-only logs (`run_events`).
* **Foreign Keys:** `<singular_entity>_id` with explicit `ON DELETE CASCADE` or `ON DELETE SET NULL` constraints. Foreign keys are never permitted across schema boundaries.

---

## 3. Timestamps & Timezones
* **Mandatory UTC:** All date/time columns must use `TIMESTAMPTZ` (`TIMESTAMP WITH TIME ZONE`).
* **Audit Columns:** Every stateful table must include:
  - `created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`
  - `updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`

---

## 4. Migration Governance (Alembic)
* **Reversible Migrations:** Every migration `upgrade()` must have an exact, working `downgrade()` function.
* **No Breaking DDL on Production:** Do not drop or rename columns in a single release. Use the expand-contract pattern:
  1. Add new nullable column.
  2. Dual-write in application code.
  3. Backfill historic data.
  4. Deprecate and drop legacy column.
* **Zero Unreviewed Autogenerate:** Inspect autogenerated Alembic files to verify no unintended table drops occur.

---

## 5. Indexing & Query Hygiene
* **Foreign Key Indexing:** Every foreign key must have a B-tree index to eliminate table-scan locks during cascaded updates.
* **Vector Embeddings (pgvector):** Use HNSW indexing (`vector_cosine_ops`) for resume and job skill vectors.
* **Compound Filter Indexes:** Order composite indexes by highest cardinality first, followed by sorting fields (`created_at DESC`).
* **No `SELECT *`:** Always select explicit model attributes in production queries.

---

## 6. Soft Deletion & Data Retention
* **Justified Soft Deletion:** Soft deletion (`deleted_at TIMESTAMPTZ`) is permitted ONLY for auditable user entities (`users`, `applications`).
* **Hard Deletion for PII:** When a candidate exercises GDPR/CCPA "Right to be Forgotten", their resume text, documents, and profile data must be permanently erased via cascaded hard deletion.

---

## 7. Backups & Disaster Recovery
* **Schedule:** Nightly automated `pg_dump` compressed backups at 02:00 UTC, encrypted with AES-256 and pushed to AWS S3.
* **Retention:** 14 daily rolling snapshots, 8 weekly archives, 12 monthly cold archives.
* **Recovery Targets:** RTO < 60 minutes; RPO < 24 hours (Phase 1), < 15 minutes (Phase 13 with streaming WAL replication).
