## 1. Migration Tooling Standards
- **Tool:** Alembic (Python).
- **Location:** `backend/alembic/versions/` for Core Engine.
- **Naming Rule:** Every migration revision must have a descriptive message:
  ```bash
  alembic revision --autogenerate -m "create_core_jobs_and_matches_tables"
  ```

## 2. Mandatory Migration Rules
1. **Never Edit Past Migrations:** Once a migration has merged to `main`, it must never be edited. Changes require a new forward migration.
2. **Reversible Migrations:** Every `upgrade()` function must have a corresponding, functional `downgrade()` function.
3. **No Breaking DDL on Production:** Large column drops or table renames must follow the expand-contract pattern across releases:
   - Phase A: Add new nullable column.
   - Phase B: Dual-write to both columns.
   - Phase C: Backfill data.
   - Phase D: Deprecate and drop old column.
4. **Zero Destructive Autogenerate:** Always inspect autogenerated Alembic files to ensure no unexpected table drops occur.
